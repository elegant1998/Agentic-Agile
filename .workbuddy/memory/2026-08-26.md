# 2026-08-26 工作日志

## Agentic-Agile-Book 图书构建工具三处 bug 修复

用户报告三个 bug，全部定位根因并修复、端到端验证通过：

### Bug 1 — EPUB 第 10 页 XML 报错（img / div mismatch）
- **根因**：`tools/assemble_book.py` 的 `assemble_from_chapters` 在 manuscript 首页插入封面时，`<img>` 标签未自闭合。pandoc 把 manuscript 转 EPUB 后，`EPUB/text/ch001.xhtml` 第 22 行 `<img ...>` 没有 `/>`，XHTML 严格 XML 解析时把后续 `</div>` 当作 img 的关闭标签，报 `error on line 23 at column 7: Opening and ending tag mismatch: img line 22 and div`。
- **修复**：第 139 行 `<img ...>` → `<img ... />`。
- **验证**：重新 build EPUB，新 `ch001.xhtml` 第 22 行已正确自闭合，epubcheck XML 报错消失。

### Bug 2 — assemble 即使指定 `--version`，manuscript 文件名和内容里的版本号都不更新
- **根因**：`tools/assemble_book.py` 第 499 行 `--manuscript` 默认值硬编码 `Path("downloads/md/Agentic-Agile-v3.1.md")`，且 `assemble_from_chapters` 只把 chapter 内容原样拼接到 manuscript，不感知 `--version`；`book/00-书名.md` 第 20 行 `> **书稿版本：v3.1 工作稿**` 也是源里写死的，导致 manuscript 内容里的版本号永远是 v3.1（实际产物已升到 v3.6）。
- **修复**：
  1. `--manuscript` default 改为 `None`。
  2. `main()` 在 `args.manuscript is None` 时按 `--version` 推导默认路径：`Path(f"downloads/md/Agentic-Agile-v{version}.md")`。
  3. `assemble_from_chapters(book, manuscript, cover, version=None)` 增加 `version` 参数，写入 manuscript 时用正则 `(\*\*书稿版本：)v[\d.]+( 工作稿\*\*)` 把版本号替换成当前 `--version`。
  4. `build_release` 把 `args.version` 传给 `assemble_from_chapters`。
- **验证**：跑 `python3 tools/assemble_book.py --version v9.9`，manuscript 写到 `downloads/md/Agentic-Agile-v9.9.md`，内容里 `> **书稿版本：v9.9 工作稿**` ✓（验证后清理）。

### Bug 3 — Portal 图书下载报"资源文件尚未发布"
- **根因**：`Agentic-Agile-Portal/server/routes/resources.ts` 第 16-17 行 `RESOURCE_FILES` 里 `book-pdf` / `book-epub` 的 `filename` 硬编码 `Agentic-Agile-v3.1.pdf` / `v3.1.epub`。`publish_to_portal.py` 已把 `v3.6` 文件复制到 `content/books/agentic-agile/downloads/`，`manifest.json` 的 `downloads[].path` 也已更新到 `downloads/Agentic-Agile-v3.6.{pdf,epub}`，但路由还在按硬编码 v3.1 找文件，找不到 → 报"资源文件尚未发布"。
- **修复**：`resources.ts` 改造为 manifest 驱动 —— `book-pdf` / `book-epub` 的 `filename` 留空，新增 `loadBookDownload(format)` 从 `content/books/agentic-agile/manifest.json` 的 `downloads[]` 查指定格式的实际 path + label；下载路由对 `source === "book"` 调用该函数，找不到再回 "尚未发布"。`runSQL` 入库的 `resource_name` 和 `res.download` 的 `displayName` 都改用动态值。这样以后版本号再升级，路由无需改代码。
- **验证**：`tsc --noEmit` 通过；最小 Node 脚本模拟路由读 manifest 后能 FOUND v3.6 PDF 和 EPUB 实际文件。
