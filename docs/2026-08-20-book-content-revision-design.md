# 《Agentic Agile 智能体敏捷》全书内容修订设计

## 修订目标

从读者阅读体验出发，把当前“概念丰富、工程部分偏重、组织部分偏薄”的稿件，修订为一条清晰的认知与行动路径：先说明为什么旧研发系统出现结构性拥堵，再说明 Agentic Agile 的总架构，随后用一个贯穿案例证明它如何运行，最后落到人员、组织和企业试点。

## 全书总地图

```text
四维重构：要改变什么
  人员 / 组织 / 流程 / 工具

3-4-3：谁负责、围绕什么运行、自治如何受控
  IO / OA / AS
  Intent Graph / Intent Contract / Constraint Matrix / Evidence Bundle
  三大自治机制

SCOPE-V：一次任务如何运行
  Specify → Constrain → Orchestrate → Prove ⇄ Evolve → Verify

Harness：如何限制和保护 Agent 执行
  上下文、工具权限、门禁、停止、恢复

Evidence：如何证明这一次任务
  契约、约束、测试、差异、风险、回退、裁决

Telemetry：如何判断组织长期是否变好
  价值、能力、效率、进化及其成本与反指标
```

### 固定定义

- 四维重构是转型对象，不是运行流程。
- 3-4-3 是相对稳定的责任、共同事实和自治架构。
- SCOPE-V 是一次任务的持续控制回路。
- Harness 是包裹 Agent 执行的约束、验证、停止和恢复系统。
- Evidence Bundle 支持单次任务裁决。
- Telemetry 支持跨任务、跨周期的组织学习。
- 3-4-3 的最后一个“3”统一称为“三大自治机制”，不再与“三条运行原则”混用。

## 公式修订

删除没有可测量依据的指数关系，改为启发式加法表达：

```text
产出 ≈ 碳基时间
     + 硅基时间 × Agent 并行数量
```

其中：

- 碳基时间：人类用于意图澄清、价值判断、系统设计、异常处理和责任裁决的投入；
- 硅基时间：Agent 在授权边界内完成检索、生成、测试、验证、修复等工作的执行时间；
- Agent 并行数量：在上下文、权限、验证和协调成本可控的前提下，同时运行的 Agent 或执行单元数量。

该公式只用于解释“执行能力如何扩展”，不能直接当作组织产出预测模型。真实产出还要扣除上下文准备、协调、验证、返工、等待和风险成本。

## 内容修订轮次

### 第一轮：结构与逻辑

- 修复前言“七个问题”实际列出八个问题；
- 统一 3-4-3、SCOPE-V、Harness、Evidence、Telemetry 的层级；
- 在前言和第五章建立同一张总地图；
- 删除或改写没有变量口径的效率公式；
- 明确第三部分各章边界，减少 Prove、Verify、Telemetry 的重复。

### 第二轮：核心章节补强

- 第十五章补充完整 Evidence Bundle、发布裁决和 UNKNOWN 场景；
- 第二十一章补充岗位变化、授权矩阵、组织案例和管理反模式；
- 附录 G 改为贯穿案例索引，并与第十至第十八章形成回链；
- 第四部分增加从任务闭环到组织试点的过渡。

### 第三轮：读者教学层

核心概念首次出现时，尽量采用“定义—例子—边界—关系—最小实践”结构；术语表只作为查阅，不再承担正文首次解释责任。

### 第四轮：作者化语言

- 减少连续使用“不是……而是……”和“真正的问题是……”；
- 保留有力度的判断，但用具体任务、人物、失败和裁决承载观点；
- 合并重复结论，增加章节之间的承接句；
- 降低“碳基 / 硅基”在普通技术段落中的重复密度。

### 第五轮：主线重排

- 第三部分只保留一次任务的核心运行闭环；
- Prove 只证明实现满足契约，Verify 只判断证据支持的行动，Telemetry 只负责跨任务长期能力，流水线只负责工程承载；
- 第十八章改为单一端到端案例；
- 原第十八至二十章的工程扩展移动到第五部分；
- 第四部分增加管理评价与企业转型路线，补足组织落地的主叙事；
- 附录案例改为工作表，避免与第十八章重复。

## 验证标准

- 全书章节顺序和标题编号连续；
- 核心术语在首次出现处可被普通研发管理者理解；
- 3-4-3 定义全书一致；
- 前言公式不再使用指数关系，并明确并行数量与成本边界；
- Verify、组织重构和贯穿案例不再明显短于相邻核心章节；
- 重新组装的 Markdown 图片路径可由 Typora 和 Pandoc 找到；
- EPUB 生成无资源警告；
- 不引入未经证实的企业数据或“必然提效”结论。
