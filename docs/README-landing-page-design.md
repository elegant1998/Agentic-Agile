# README 首页设计稿

日期：2026-08-20

## 目标

让第一次进入仓库的陌生访客在短时间内理解本书解决的问题、判断自己是否适合阅读，并产生下载 PDF/EPUB 的动机。

## 目标读者

同时服务两类读者：

- CTO、研发管理者、AI 转型负责人：关心人员、组织、流程与工具如何重构。
- 架构师、FDE、工程师与 AI 工程团队：关心 Agent 如何被授权、执行、验证、恢复并在越界时停止。

## 页面结构

1. 宣言式首屏：以“AI 已经会执行，研发组织准备好重新设计了吗？”建立问题张力。
2. 现实矛盾：代码更多但需求仍排队、Agent 更快但测试审核成为瓶颈、工具增多但责任证据仍分散。
3. 双入口：分别指向管理者关心的组织重构问题和工程师关心的 Agent 运行闭环。
4. 方法体系：用“意图 → 约束 → 编排 → 执行 → 验证 → 证据 → 遥测 → 进化”展示全书主线。
5. 阅读收益：把正文的核心问题转换成具体的认知与行动收获。
6. 下载入口：明确提供 PDF、EPUB 与 GitHub Releases，并说明版本以 Release 为准。
7. 作者与许可：置于末尾，作为可信度与使用边界说明。

## 发布与维护结构

- `book/` 下的分章 Markdown 是公开阅读版，也是未来维护的唯一正文源。
- 私有总稿只作为本次迁移输入，迁移完成后不再作为维护制品。
- 本地 `tools/assemble_book.py` 按固定目录顺序生成合并总稿，供 PDF/EPUB 排版或发布流程使用；脚本不进入公开仓库。
- `pic/` 是本次迁移的临时素材入口；脚本只复制正文实际引用的图片到 `book/assets/pic/`，完成后可删除临时目录。
- 公开版本以章节文件、合并总稿摘要和 PDF/EPUB 的同一版本号绑定，避免单章修改与下载制品失配。

本地操作约定：

```bash
# 首次迁移：一次性总稿拆成公开章节
python3 tools/assemble_book.py --split --clean --source "旧总稿.md"

# 日常维护：从 book/ 分章重新组装排版输入
python3 tools/assemble_book.py
```

## 内容约束

- 忠实于正文开篇，不虚构出版信息、读者评价、销量或外部背书。
- 保留“换操作系统”、AI First / AI Native、3-4-3、SCOPE-V、验证工程等核心锚点，并用白话解释术语。
- 公开完整正文，但按章节组织；README 负责入口和导流，不承载全文。
- 不把方法体系写成孤立术语清单，必须说明它们如何构成从意图到证据的闭环。
- 不承诺当前尚未提供的 PDF/EPUB 文件；下载位置以实际 Release 或目录内容为准。

## 验收标准

- 首屏前几段能同时回答“这是什么”和“为什么现在值得读”。
- 管理者与工程师都能找到对应入口。
- README 包含 PDF、EPUB、GitHub Releases 的明确链接。
- README 明确正文按章节公开，私有总稿与本地组装脚本不进入公开仓库。
- `git diff --check` 通过，且正文 Markdown 仍被 `.gitignore` 排除。
- `book/` 的章节文件可由本地脚本重新生成，图片引用不出现断链。
